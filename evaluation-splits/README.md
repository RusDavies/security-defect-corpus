# Evaluation Splits

`case-splits.json` is generated by `scripts/generate_evaluation_splits.py`.
It assigns every ground-truth case to a deterministic development, validation,
or held-out split using the case ID.

Held-out entries also list mutation axes. Final generalization claims should use
mutated held-out variants rather than exact checked-in fixtures, because exact
fixture recognition is not the same thing as security reasoning. Shocking, yes.

Use:

```bash
python3 scripts/generate_evaluation_splits.py --check
```

The split manifest is not a secrecy boundary by itself; it is an evaluation
discipline boundary. Reports should still disclose whether the evaluated system
had access to the corpus, expected outputs, harnesses, or derived variants.
